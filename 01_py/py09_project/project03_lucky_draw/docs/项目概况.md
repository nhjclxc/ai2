# 一、抽奖系统是干什么的（整体认知）

一个抽奖系统，本质就是：

👉 **在一堆奖品中，按照规则和概率，随机选一个给用户**

但真实业务远比“random.choice”复杂，核心会涉及：

* 概率控制（不能真的完全随机）
* 库存控制（奖品不能发超）
* 用户限制（一天只能抽3次）
* 活动规则（新用户必中一次）
* 防刷（接口不能被刷爆）
* 可配置（运营要能改）

---

# 二、核心功能模块拆解

我给你拆成 6 大模块，每个模块都是你后端要设计 API 和数据结构的重点。

---

## 1️⃣ 活动管理模块（Campaign / Activity）

👉 用来定义“抽奖活动是什么”

### 功能点：

* 创建活动
* 编辑活动
* 上线 / 下线
* 活动时间控制（开始时间 / 结束时间）

### 核心字段设计：

```python
Activity:
- id
- name
- status (draft / online / offline)
- start_time
- end_time
- rule_config（JSON，存规则）
```

---

## 2️⃣ 奖品管理模块（Prize）

👉 定义“可以抽到什么”

### 功能点：

* 添加奖品
* 设置概率
* 设置库存
* 奖品类型（不同发放方式）

### 奖品类型（非常关键）：

* 实物（需要发货）
* 虚拟（优惠券、会员）
* 谢谢参与（空奖）

### 核心字段：

```python
Prize:
- id
- activity_id
- name
- type (physical / virtual / none)
- probability
- stock
- total_stock
```

---

## 3️⃣ 抽奖核心模块（Draw Engine）

👉 系统的“心脏”，你必须重点实现

### 功能：

* 根据概率抽奖
* 判断库存
* 生成中奖结果

### 抽奖逻辑流程：

```text
1. 校验用户是否有抽奖资格
2. 获取活动奖品列表
3. 按概率计算中奖结果
4. 校验库存（防止超发）
5. 扣减库存（必须原子操作）
6. 返回结果
```

---

## 4️⃣ 用户参与模块（User Draw Record）

👉 控制“谁可以抽、抽了几次”

### 功能：

* 每日次数限制（如每天3次）
* 总次数限制
* 特殊规则（新用户必中一次）

### 核心字段：

```python
UserDrawRecord:
- user_id
- activity_id
- draw_count
- last_draw_time
```

---

## 5️⃣ 抽奖记录模块（Log / History）

👉 记录所有抽奖行为（非常重要！）

### 功能：

* 查询用户中奖记录
* 审计 / 防作弊
* 数据统计

### 核心字段：

```python
DrawLog:
- id
- user_id
- activity_id
- prize_id
- result (win / lose)
- created_at
```

---

## 6️⃣ 风控 / 限流模块（Anti-Abuse）

👉 防止系统被刷爆

### 基本能力：

* IP 限流
* 用户限流
* Token 校验
* 防重复提交


```json
    "name": "10元优惠券"
  }
}
```


# 四、关键技术难点（你必须考虑）

这里是面试 / 实战的重点👇

---

## 1️⃣ 概率算法

不能简单 random，要支持：

* 权重随机（Weighted Random）
* 动态概率（库存越少概率越低）

👉 推荐实现：

```python
random.choices(prizes, weights=probabilities)
```

---

## 2️⃣ 库存扣减（高并发问题）

必须避免：

❌ 超发库存
❌ 并发抢同一个奖品

👉 解决方案：

* Redis 原子扣减
* 数据库乐观锁
* Lua 脚本

---

## 3️⃣ 并发控制

抽奖接口是高并发入口：

* 加锁（Redis Lock）
* 限流（如令牌桶）

---

## 4️⃣ 防作弊

* 同一用户刷接口
* 模拟请求

👉 方案：

* 限频
* 签名校验
* 行为分析
